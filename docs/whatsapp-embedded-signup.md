# WhatsApp Embedded Signup

wacrm is multi-tenant: every account connects its own WhatsApp Business
number in **Settings → WhatsApp**. This doc covers the **"Connect with
Meta"** button — Meta's official Embedded Signup flow — which is the
recommended way for a tenant to connect, and the **one-time setup an
operator of this wacrm deployment** must do in Meta for Developers
before that button works.

The old manual form (paste `phone_number_id` / WABA ID / access token by
hand) still exists as an "Advanced" fallback in the same screen — for
reconnecting with a hand-rotated token, or debugging. It is not
affected by anything below.

## Why this exists

Every deployment of wacrm has exactly one Meta App, identified by
`META_APP_ID` / `META_APP_SECRET` in the environment. The webhook
handler verifies every inbound request's HMAC signature against that
**one** `META_APP_SECRET`, regardless of which tenant it's for.

Before this flow existed, connecting a new tenant's number meant the
operator pasting in credentials the tenant had generated by hand in
*their own* Meta for Developers account — including, easily, a WABA
attached to a brand-new Meta App the tenant created themselves rather
than wacrm's. A WABA registered under a different App can never
validate against wacrm's `META_APP_SECRET`, so its inbound webhooks
fail silently (this is exactly what happened with the Biosol tenant in
production).

Embedded Signup fixes this structurally: the popup only ever authorizes
**wacrm's own App** (identified by the `config_id` created below), and
the backend explicitly subscribes that App to the tenant's WABA
(`POST /{waba_id}/subscribed_apps`) as part of finishing the connection.
There is no path through this flow that lands a tenant's WABA on the
wrong App.

## One-time setup (operator, not per tenant)

Everything in this section is done **once for the entire wacrm
deployment**, by whoever administers its Meta App — not by each
tenant, and not once per tenant. A tenant's operator-facing step is
just clicking "Connect with Meta" in Settings → WhatsApp.

1. **Use (or create) wacrm's Meta App.**
   Go to [developers.facebook.com](https://developers.facebook.com) →
   **My Apps**. This should be the same App whose `META_APP_ID` /
   `META_APP_SECRET` are already in wacrm's environment (see
   `.env.local.example`) — the one the webhook and template-upload
   features use today. Do not create a second App for this.

2. **Add both required products**, if not already added: App dashboard →
   **Add Product** → **WhatsApp** → **Set up**, and separately →
   **Add Product** → **Facebook Login for Business** → **Set up**.
   Embedded Signup configurations live under Facebook Login for
   Business, not under the WhatsApp product itself — see step 3.

3. **Create an Embedded Signup configuration.**
   In the App dashboard: **Facebook Login for Business → Configurations
   → Create configuration**. (This moved out from under the WhatsApp
   product's own menu at some point after v2/v3 — if you're looking at
   an older screenshot or an older revision of this doc, ignore it and
   use Facebook Login for Business instead.)
   - Give it a name (e.g. `wacrm-production`).
   - Choose the WhatsApp Business permissions/features you want the
     popup to request. For wacrm's use case, the defaults covering
     `whatsapp_business_management` and `whatsapp_business_messaging`
     are sufficient.
   - Save it. Meta shows a **Configuration ID** — this is the
     `config_id` this doc refers to everywhere below. Copy it.

   This configuration is what makes the popup show *your* branding and
   request exactly the permissions wacrm's backend needs — it's
   metadata attached to your App, not something tied to any one
   tenant.

4. **Set the deployment's environment variables** (see
   `.env.local.example` for the full comments):

   ```
   META_APP_ID=<your App ID>                                    # already required; also client_id for code exchange
   META_APP_SECRET=<your App Secret>                            # already required
   NEXT_PUBLIC_META_APP_ID=<same App ID as META_APP_ID>          # SDK runs client-side
   NEXT_PUBLIC_META_EMBEDDED_SIGNUP_CONFIG_ID=<config_id from step 3>
   ```

   Restart/redeploy so the new `NEXT_PUBLIC_*` values are baked into
   the client bundle. If either `NEXT_PUBLIC_*` var is missing, the
   "Connect with Meta" button is hidden and Settings → WhatsApp shows
   only the manual/advanced form — nothing breaks, the feature is just
   inactive.

5. **App review / Business verification.** While your App is in
   Development mode, Embedded Signup only works for people with a role
   on the App (admin/developer/tester) in Meta Business Manager. To let
   arbitrary tenants connect their own numbers, the App needs **Business
   verification** and the **`whatsapp_business_management`** +
   **`whatsapp_business_messaging`** permissions approved for **Advanced
   Access** via App Review. This is a one-time Meta process
   (typically hours to a few days) — plan for it before relying on this
   flow for real customer onboarding.

There is nothing else to configure per tenant. A tenant's admin clicks
"Connect with Meta", picks/creates their WABA and number in Meta's
popup, and wacrm's backend does the rest (code exchange, webhook
subscription, and — if needed — phone number registration).

## What happens when a tenant clicks "Connect with Meta"

1. The browser loads Meta's Facebook JS SDK and calls `FB.login()` with
   the `config_id` from step 3 above.
2. The tenant's admin logs into Meta (or is already logged in), picks
   or creates their WABA and phone number, and authorizes wacrm's App.
3. Meta's popup returns an authorization **code** via the `FB.login()`
   callback, and separately **posts a `message` event** to the opener
   window with the chosen `waba_id` / `phone_number_id`:

   ```json
   {
     "type": "WA_EMBEDDED_SIGNUP",
     "event": "FINISH",
     "data": { "phone_number_id": "1234...", "waba_id": "5678..." }
   }
   ```

   (`event` can also be `CANCEL` or `ERROR` — surfaced in the UI as a
   toast.) wacrm's frontend (`whatsapp-config.tsx`) listens for both
   the callback and the message, and once it has all three pieces
   (`code`, `waba_id`, `phone_number_id`), posts them to the backend.

4. `POST /api/whatsapp/embedded-signup` (session-authenticated, writes
   only to the caller's own account — never a client-supplied
   `account_id`):
   - Exchanges `code` for a real access token via
     `GET /oauth/access_token` using `META_APP_ID` / `META_APP_SECRET`.
   - Verifies the token against the chosen `phone_number_id`.
   - Calls `POST /{waba_id}/subscribed_apps` — this is the step that
     actually fixes the multi-App bug; it's never skipped.
   - Calls `POST /{phone_number_id}/register` (with a freshly generated
     PIN, since a number fresh out of Embedded Signup has no existing
     2-step PIN to reuse) unless this exact number was already
     registered for this account.
   - Encrypts the access token (`ENCRYPTION_KEY`, same helper the
     manual form uses) and upserts the account's `whatsapp_config` row
     — updating in place on reconnect, never duplicating it.

5. The UI re-fetches the config and shows the same "Registered" /
   "Not registered" status the manual flow already surfaces, with the
   same "Verify with Meta" retry path if registration didn't complete.

## Troubleshooting

- **Button is hidden.** `NEXT_PUBLIC_META_APP_ID` or
  `NEXT_PUBLIC_META_EMBEDDED_SIGNUP_CONFIG_ID` isn't set for this
  deployment — see step 4 above.
- **Popup opens but nothing happens after picking a number.** Check the
  browser console for `message` events from `facebook.com` /
  `web.facebook.com` — Meta occasionally changes the event shape across
  SDK versions; compare against the JSON shape in this doc.
- **"Meta code exchange failed."** The authorization code is single-use
  and short-lived — if the popup flow was retried or the tab sat open
  too long, just click "Connect with Meta" again.
- **Saved but "Not registered."** Same failure mode the manual flow can
  hit — click "Verify with Meta" on the Registration status banner for
  a diagnostic, or reconnect via the button again.
- **Popup fails immediately with "No pudimos verificar tu información /
  No se pudo compartir la cuenta de WhatsApp Business con los socios"
  (an `(#N/A:...)` trace ID, different each attempt).** This fires
  *inside Meta's popup*, before `FB.login()`'s callback or the
  `message` listener ever run — nothing reaches our frontend console
  or backend logs, so it isn't caused by `config_id`, the `extras`
  passed to `FB.login()`, or anything else in this repo. It matches
  Meta's documented restriction that a WABA originally created by hand
  via the App dashboard (App → WhatsApp → API Setup) is not eligible
  for Embedded Signup sharing/onboarding, even after deleting and
  recreating that WABA. Confirmed for the Biosol number in 2026-07;
  see the "Existing WABAs" caveat on Meta's Embedded Signup overview
  doc. The fix has to happen on Meta's side (new WABA created *through*
  Embedded Signup itself, or Meta support) — there is no code-side
  workaround.
- **"This WhatsApp phone number is already linked to another account."**
  wacrm is one-number-per-account; someone already connected this exact
  number under a different account on this instance.
